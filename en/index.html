Samuel has been working in software for over four years, mostly with PHP/Laravel and Vue 3 with TypeScript, with some .NET along the way. Architecture and code quality are what he cares about most in the job.

At Nocartório, a management SaaS for Brazilian notary offices, he mostly works on legally valid PDF generation and search. There, a certificate can’t gain an extra page and search can’t disappear when the cluster goes down.

Before that, he worked at CCO Bank (Flutter and .NET), Techmind Solutions (.NET and React) and CloudOpss Solutions (Python automation).

Outside work, he trained a car model classifier with transfer learning (EfficientNet) on the public UTFPR-CMMD dataset. Test accuracy went from 61% to 78%, and the conclusion he wrote down is that the next gain would come from the data, not the model.

Journey

Journey • Journey • Journey • Journey

Started out automating data collection with Python, then moved through banking and high-volume document generation. Now at a SaaS for notary offices.

  • Led the move from three legacy PDF engines to a single engine (tc-lib) for books and certificates in every specialty, with the legacy page count guaranteed by tests. Then removed the legacy code, including the Python PDF service he had maintained himself.
  • Moved draft images out of the HTML and into storage, with chunked uploads and async extraction. Autosave for a 347-page PDF dropped from 155 MiB to 7.7 KB.
  • Isolated PDF rasterizing in a Rust microservice with PDFium, with no secrets and no network access, and removed Ghostscript from the main app.
  • Made search over ~6 million profiles self-healing (Elasticsearch/Laravel Scout).
  • Took the book test suite from 3h20 to 12 minutes.
  • Led the admin area migration from Blade/jQuery to Vue 3, Inertia and TypeScript, and the file storage move from Azure Blob to OCI Object Storage.
